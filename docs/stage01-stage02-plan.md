# 远程工作台与企业 AI 实施计划

## Stage 01

- 保留现有日志解析、筛选、源码导航及浅色/深色视觉体系。
- 首次使用：打开远程 → 添加主机凭据 → 可独立测试 → 保存并浏览 → 双击打开文件。显示名称默认主机，收藏目录可空且不是访问白名单。
- 日常使用：切换服务器、输入路径、收藏、上级、刷新、文件打开；路径输入与真实 SSH 命令分开。命令支持 shell 语法，执行后的 cwd 同步浏览目录。SMB 保留共享文件访问，不假装具备 SSH。
- 优化每次目录操作重新连接及冗余探测；验证连接复用、失败恢复、目录更新、下载完整性。区分模拟高延迟测试与真实服务器结果。
- 适当粒度提交，仅包含本次文件；stage 完成推送当前仓库配置的 origin 分支。

## Stage 02

- 对照 OpenCode v1.2.27 官方源码确认 serve 协议，以企业配置的内部 agent 为唯一 AI 接口。
- 支持独立日志工作区与源码仓库工作区；日志和会话持久化，原始日志可重新打开，多会话可切换。
- ERROR 汇总、右键选中行、全文确认三种入口；自动展开可移动/调整大小的 AI 窗口，历史窗口按名称、时间、来源区分。
- 可选诊断提示词与 agent 安装，默认不修改源码仓库；用户选择安装及跟踪日志时仅处理该功能自己的文件。
- 验证 API 契约、持久化恢复、源码工作区、取消/错误流程、浏览器端完整交互；企业定制服务未提供时明确区分契约模拟与真实 OpenCode。

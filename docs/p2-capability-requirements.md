# P2 能力需求边界与性能预算

状态：**需求设计，未实现**。本文不代表相关 UI、流式加载器、多文件索引、工作区或 AI 回链已经交付。

基线约束：保留初始格式拖入、默认搜索只定位、现有解析/筛选语义、历史快照与后端契约。任何 P2 能力均为独立、可选入口，不能以牺牲现有小文件同步路径为代价。

## 0. 统一验证口径

以下数值是后续实现的验收预算，不是当前版本实测结果。

- 基准客户端：4 核桌面 CPU、16 GB 内存、Chromium 稳定版、本地文件、无其他高负载任务；分别记录冷/热缓存。
- 每组至少运行 5 次，报告中位数与 P95；同时报告文件大小、物理行数、记录数、堆栈比例和失败比例，禁止只报 MB/s。
- 主线程长任务、Worker 耗时、峰值 JS 堆、传输字节数分别测量；开发模式数据不用于性能结论。
- 1 GB 指 1,000,000,000 字节。UTF-8 多字节文本须纳入样本；正常日志、超长行、堆栈与损坏行分层测试。
- 小文件回归门槛：10,000 行内置示例的记录、字段、顺序、错误数和搜索匹配数与当前版本一致；100 MB 内现有路径的 P95 交互耗时不退化超过 10%。
- 响应性预算均以页面可见、可取消、焦点可操作为准；后台解析完成时间不能代替首屏和交互指标。

## 1. 大文件流式 / 分块解析

### 需求与独立边界

用户应能打开大于当前一次性 `FileReader.readAsText` 适用范围的本地文件，尽快看到首批记录，并在后台读取期间定位、筛选和取消。明确展示已读取字节、记录数和“结果尚未完整”状态。

包含：
- 文件流分块、UTF-8 跨块字符拼接、记录边界拼接和堆栈聚合。
- Worker 内解析、首批发布、增量索引、进度、暂停/取消和错误恢复。
- 已加载范围内搜索；全量搜索必须等待索引完成或明确标为后台扫描。

不包含：
- 修改现有格式解析结果、默认搜索为过滤、远程协议改造或自动请求远端全文。
- 在内存中保存一份完整字符串再宣称“流式”。
- 将未加载区间产生的 0 匹配展示为全文 0 匹配。

### 技术方案

1. 以 `Blob.stream()`/`FileReader` 分块为输入，默认 4–8 MiB 自适应块；保留跨块尾行和最后一个字节序列。
2. 在 Worker 复用现有格式/解析器语义，增加按记录边界增量调用的适配层；主线程只接收批量记录和统计增量。
3. 首批 1,000–5,000 条或 2 MiB 记录即渲染；后续按时间片批量提交，虚拟表保持滚动锚点。
4. 原始文本、结构化字段、搜索索引分别计量；取消时终止 Worker 并释放缓冲区。筛选与导航只基于已发布记录，结果带覆盖范围。
5. 小文件继续使用当前同步加载路径；只有阈值以上文件进入新路径，并提供失败回退提示而非静默换算法。

### 性能预算

- 1 GB 本地文本：首批可交互记录 P95 ≤ 2 秒；读取+解析期间主线程单个长任务 ≤ 50 ms。
- 滚动、搜索输入与筛选交互 P95 ≤ 100 ms；取消到 UI 恢复可用 P95 ≤ 200 ms。
- 增量处理吞吐量 P50 ≥ 50 MB/s；不得因渲染批量过大出现连续 1 秒无响应。
- 峰值额外 JS 堆预算 ≤ 1.5 GiB，且不超过文件字节数的 1.5 倍 + 512 MiB；超限前主动降速或提示，不崩溃。
- 记录边界与统计必须零丢失、零重复；同一文件与格式下结果与现有解析器一致。

### 验收指标

- 跨块中文/emoji、CRLF、无末尾换行、1 MiB 单行、Java/Python 堆栈的字段与行号一致。
- 100 MB、1 GB 样本首屏/吞吐量/峰值内存达标；10%, 50%, 90% 进度处均可滚动和取消。
- 未完成时范围提示始终可见；完成后提示消失，最终记录数和匹配数确定。
- 后台读取时再次拖入或切换格式，不会把旧 Worker 结果写入新现场。

## 2. 多文件时间线

### 需求与独立边界

用户主动添加多个同类或不同格式日志后，可以按统一时间顺序查看跨文件事件，并始终识别来源文件与原始行号。单文件拖入仍保持当前行为，不自动合并目录或历史文件。

包含：
- 显式文件集合、逐文件格式与解析状态、来源标识、时区/无时间戳策略。
- 稳定归并、跨文件定位/筛选、来源维度移除和错误隔离。
- 大文件未完整加载时的时间覆盖范围提示。

不包含：
- 推断因果、分布式追踪 ID 自动关联、时钟漂移校正或服务拓扑。
- 改写原文件、把时间戳转换结果写回原文，或将多文件自动送入 AI。
- 在缺少可靠时间戳时伪造顺序；无时间戳记录进入独立分组，不混入确定时间线。

### 技术方案

1. 建立 `fileId + parserId + physicalLineNumber` 稳定记录键；保存来源、格式、时区和加载状态。
2. 各文件先按现有规则解析，再用 k 路堆归并有序游标，复杂度 O(N log F)；相同时间戳按文件添加顺序、物理行号稳定排序。
3. 时间戳统一为 epoch 毫秒展示，原文保留；无法解析或无时区字段按所选格式规则处理并计数。
4. 使用稀疏时间索引与虚拟列表定位，避免一次性构造完整 DOM；筛选条件复用现有语义并增加可选来源条件。
5. 与流式加载器通过记录流接口组合，但不要求两者同期交付；先支持已完整加载的小文件集合。

### 性能预算

- 基准：20 个文件、合计 100 万条记录；完整索引后首屏 P95 ≤ 2 秒，归并索引 P95 ≤ 8 秒。
- 时间线翻页/定位 P95 ≤ 100 ms；来源筛选 P95 ≤ 300 ms；输入期间主线程长任务 ≤ 50 ms。
- 除已解析记录外的归并/时间索引额外内存 ≤ 256 MiB；文件数增加到 100 时不得退化为全量重复排序。
- 对重复时间戳、空文件、单文件损坏均保持确定性排序和可解释计数。

### 验收指标

- 2、20、100 文件归并顺序稳定；跨格式、毫秒边界、重复时间戳、时区和无时间戳用例准确。
- 移除单个文件只影响其记录，其他文件行号、筛选与定位不漂移。
- 每个记录可回到来源快照和原始行；文件未读完时不错误宣称全局最早/最晚。
- 单文件拖入和默认搜索导航结果与当前版本一致。

## 3. 调查工作区

### 需求与独立边界

工作区用于恢复“多个来源 + 调查视图 + 当前调查上下文”的容器；它不同于 P1 的单一调查视图，也不同于原文历史快照。P1 已完成的能力不因此扩展为多文件或原文复制。

包含：
- 可命名工作区、来源快照引用、文件/视图排列、活动视图和 AI 会话引用。
- 重开、重命名、删除、缺失来源报告、存储版本迁移。
- 用户显式选择是否纳入某个来源或 AI 会话；默认不复制原文。

不包含：
- 多人协同、云同步、账号权限系统、自动上传原文或凭据。
- 把远程连接密码写入工作区，或自动执行终端/AI 请求。
- 将快照引用失效伪装为恢复成功。

### 技术方案

1. 定义带版本的工作区清单，仅保存历史快照 ID、来源元数据、调查视图 ID、布局与 AI 会话 ID；原文继续由历史存储唯一持有。
2. 浏览器本地保存轻量清单，较大布局状态可放 IndexedDB；保存操作原子化，保留上一可用版本。
3. 恢复分两步：先校验所有引用并展示缺失项，再由用户确认打开；禁止恢复时自动发送 AI 请求或连接远程终端。
4. 多文件引用组合依赖“多文件时间线”的文件键；没有该能力时，工作区先限定为单活动来源，不能提前宣称支持时间线。
5. 删除工作区默认只删除清单，不删除原文历史或 AI 会话；删除原文单独确认并显示受影响工作区。

### 性能预算

- 单工作区默认 ≤ 50 个来源引用、≤ 100 个调查视图引用；序列化清单 ≤ 1 MiB，且不包含 `content`/`rawText` 正文。
- 本地保存 P95 ≤ 50 ms，读取并展示引用校验结果 P95 ≤ 300 ms（不含原文下载和解析）。
- 恢复操作只加载活动来源，非活动来源不得产生正文网络流量；取消后无孤立加载任务。
- 清单损坏或版本不支持时保留原数据并提供错误，不覆盖为空工作区。

### 验收指标

- 保存→刷新→恢复后来源、视图、布局和 AI 引用准确；快照被删除时明确列出缺失项。
- 工作区删除不影响历史原文；历史删除不会留下无提示的“成功恢复”入口。
- 本地存储中无原文正文、远程密码或令牌；恢复不会自动触发 AI/终端副作用。
- 单来源调查视图现有保存、恢复、删除行为不回归。

## 4. AI 结论回链日志行

### 需求与独立边界

AI 输出中的证据引用应可点击，定位到生成该结论时所用历史快照的原始物理行/记录范围。回链是证据导航，不证明模型结论正确。

包含：
- 带快照 ID、起止行、精确原文摘录的结构化引用；验证、展示、定位和失效提示。
- 对无引用文本保持普通 Markdown；对不明确或重复定位给出候选而不是随机跳转。
- 保持现有 AI 会话协议可兼容，引用作为响应旁的附加数据或保守标注解析。

不包含：
- 自动相信模型给出的行号、跨快照猜测位置、修改模型结论或用回链替代源码跳转。
- 变更默认搜索语义、自动发起二次 AI 请求，或在本文阶段新增后端流式协议。

### 技术方案

1. 提交分析时保存不可变 `logId` 与发送范围映射；优先要求模型返回 `{logId, startLine, endLine, quote}` 引用数组。
2. 接收端先验证快照身份、行范围和 `quote` 是否精确匹配；只有验证通过的引用才可点击。无效引用显示“无法验证”，不导航。
3. 若旧协议只能返回文本，可在前端解析明确标注并生成旁路引用，不改变现有消息结构；结构化协议升级另行评审。
4. 点击后打开对应历史快照并复用 `targetNavLog`/行定位，保留筛选只定位语义；堆栈范围定位到所属记录。
5. 快照缺失、内容变化、范围越界或摘录不匹配时展示原因，并允许复制引用文本。

### 性能预算

- 1 MiB AI 文本的引用解析 P95 ≤ 50 ms；单条消息最多处理 50 个可交互引用，超出部分折叠，防止病态输入阻塞。
- 已打开同一快照时，回链到选中并滚动 P95 ≤ 100 ms；不同快照只计导航 UI 响应，正文加载单独计时。
- 每条引用最多一次范围验证和一次受控摘录查找，禁止对每条引用全文反复扫描；大文本引用处理不得产生 > 50 ms 主线程长任务。
- 不允许未经用户操作触发额外模型 token、远程读取或源码索引构建。

### 验收指标

- 单行、堆栈范围、多条引用可回到正确快照与原始物理行；筛选后仍不改变结果集。
- 错快照、越界行、篡改行号、错误 quote、重复候选、快照删除均不能误跳。
- 旧会话和普通 Markdown 正常显示；源码帧入口与日志行回链保持各自语义。
- 引用解析和定位达到预算，且完整 AI 选中行/ERROR/全文与恢复流程回归通过。

## 5. 依赖与交付决策

四项可独立评审，但组合时有明确依赖：多文件时间线可复用流式记录接口；完整工作区依赖来源引用与多文件稳定键；AI 回链只依赖不可变历史快照和行号映射，不要求前三项先完成。

每项进入实现前分别补交互稿、异常样本和基准脚本；任何一项未完成都不能在其他项目中标记为“已支持”。本期只交付以上边界与预算。

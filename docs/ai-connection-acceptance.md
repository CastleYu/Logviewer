# 已有实例优先与 cmd 回退验收

连接策略统一为已有实例优先，连接失败或地址为空才启动配置的 cmd/exe。旧 `launch` 开关仅保留配置兼容，不再影响顺序。

通过的行为测试：

- `verify:ai-runtime`：IP:port 与三种环境变量引用、已有实例优先且不 spawn、空地址/认证失败回退、受管目录复用、外部实例不被回收、程序未配置、无法启动、提前退出、启动后无法连接的阶段化错误。
- `verify:ai`：原有目录隔离、异步消息、权限/追问、历史会话、源码日志精确暂存通过，避免连接策略改变影响原有分析链路。
- `verify:managed`：真实 Windows PowerShell 5 与原生 Job；PATH 查找 cmd，带空格的 cmd 路径，关闭 stdin 回收，只杀监督进程单个 PID 回收，以及只杀应用 owner Node 单个 PID 后回收。测试没有使用 `/T` 来掩盖父进程归属问题；程序缺失返回 71。
- 生产包浏览器：已有实例失败后通过带空格的 cmd 启动并显示成功；已有实例可达时即便回退程序无效仍直接连接；两者失败时展示各自原因。
- TypeScript 与生产构建通过。Windows 的强制终止测试有实际进程/端口证据；非 Windows 的进程组/管道监督分支未在本机执行。

Windows Job 在目标代码执行前建立归属，kill-on-close 负责清理整个受管子树；原生等待主进程句柄并结合 stdin EOF，覆盖主进程被强制结束。只管理本应用启动的 server，通过地址连接的外部实例不属于清理范围。

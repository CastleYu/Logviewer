# 企业内网 AI 与日志历史

运行 `npm ci`、`npm run build`、`npm start`。离线部署时预先准备依赖和构建产物；运行中的页面没有外部字体/CDN请求，也不包含公网模型 SDK。LogViewer 的 HTTP 桥接服务绑定本机回环地址。

## 接入内部 Agent

在右下角 **AI 设置** 填写已有实例的 `IP:端口`（也支持完整 HTTP(S) 地址）、用户名和密码环境变量名；密码值只由后端从进程环境读取。地址和回退程序路径支持 `%变量名%`、`${变量名}`、`$env:变量名`，例如 `%AGENT_HOST%:%AGENT_PORT%`。输入 `opencode.cmd` 可从服务进程的 PATH 查找；也可填写 `%AGENT_HOME%\opencode.cmd` 或 exe 绝对路径。设置中的 Provider ID / Model ID 应来自企业 Agent 的内部模型。应用只连接回环/私有地址，不直接请求模型供应商；Agent 自身的模型和工具网络出口仍由企业部署策略管理。

连接顺序固定为：先探测已有实例的认证与目录作用域；未填写地址或实例无法连接时，自动使用 **回退启动程序（cmd / exe）**，追加 `serve --hostname 127.0.0.1 --port <自动端口>`。程序须保持前台运行并转发参数。同一工作区复用自启动进程。无需额外启动开关，旧配置的 `launch` 值不改变这个顺序。**测试连接与回退**会执行同一流程，并显示最终使用已有实例还是自启动实例。

只有两条路径都失败才报错，错误会组合已有实例失败原因与回退阶段：未配置启动程序、无法启动程序、程序启动后提前退出、程序已启动但 server 无法连接/未就绪。认证失败、环境变量缺失、目录不匹配会明确说明。

Windows 自启动进程使用原生 Job Object（kill-on-close），目标进程先以 suspended 状态创建，加入 Job 后才执行；监督进程等待应用进程句柄和父进程管道关闭。应用后端正常关闭或被强制结束时，所属 server 及其子进程会一同回收。通过 IP:端口连接的已有实例不加入本应用 Job，也不会被关闭。浏览器页面关闭不等于本机后端进程退出。企业 Agent 需事先安装和配置，不会在运行时下载 Agent；自启动关闭了 OpenCode 自动更新和模型目录抓取。

## 两种工作区

| 模式 | 日志与源码 | 适用场景 |
|---|---|---|
| 隔离日志 | 为历史日志 ID 创建独立工作目录，保存 `input.log`，在该目录初始化 Git 并仅暂存日志以兼容只读 tracked files 的内部 Agent | 无源码，梳理错误分类、时间线和待核实假设 |
| 源码工作区 | 选择源码索引中的目录或输入绝对路径；默认以提示词传入选定日志，不写入源码仓库 | 结合源码调用链、配置和日志分析 |

源码模式可选 **复制日志并 git add 此文件（不提交）**：仅创建并暂存 `.logviewer-ai/<历史ID>/input.log`，保留仓库其余暂存内容，不提交或推送。一个历史日志保存一个默认仓库映射；新会话可以重新选择仓库。**浏览并索引**复用现有源码索引功能。

连接、工作区及安装设置用于新会话；已有会话保留原目录和服务地址，避免配置修改后串到其他 Agent。日志数据和服务必须位于同一可访问文件系统：连接其他主机上的 serve 时，源码路径必须在该主机存在；本机自动创建的隔离目录适合本机 Agent。

## 日常操作

- **分析 ERROR**：发送当前完整日志中所有 ERROR/FATAL 记录，包含堆栈原文与日志行号，不受表格筛选影响。
- 表格右键 **AI 分析选中行**：发送所选记录并自动展开 AI 窗口。内置和可配置格式均支持。
- **分析全文**：先显示字符数及粗略 token 数，确认才发送，取消不发起分析请求。实际模型上下文上限由企业 Agent 返回。
- AI 窗口可拖动、调整大小、切换或新建会话、追问、停止；权限与追问按当前会话展示和回复。长日志输入折叠展示，完整提示词仍会保存。
- 断线仍能浏览缓存对话，可点击 **重新同步会话**恢复服务侧状态。异步 HTTP 204 仅表示受理，不会当作分析完成。
- **历史日志**按名称/来源搜索，显示打开时间和来源；每次打开保存独立快照，因此同名文件不会覆盖。本地路径打开保留绝对路径，远程日志保留主机地址及远程路径。普通浏览器拖入文件受浏览器限制无法取得绝对路径，会明确显示“未提供完整路径”。

## 可选诊断方法

**RCA prompt / recipe**可开关比较普通提示和诊断范式：时间线、请求/trace/span 关联、首个故障与级联错误、源码证据、反证和最小验证。方法参考 [Google SRE troubleshooting](https://sre.google/sre-book/effective-troubleshooting/) 与 [OpenTelemetry 日志模型](https://opentelemetry.io/docs/specs/otel/logs/data-model/)。

可选安装两个项目级 Agent 文件：`.opencode/agents/logviewer-diagnose.md`（primary）和 `logviewer-evidence.md`（subagent）。已有同名文件不覆盖；关闭提示词开关可进行基线比较。源码模式的安装在创建会话前完成；选用安装的主 Agent 时在 Agent 字段填写 `logviewer-diagnose`。不需要安装公网 MCP 服务。企业自有 MCP 的 v1.2.27 配置示例与研究来源见 [接口研究](stage02-opencode-research.md)。

## 持久化与验证

`.logviewer-history/`保存每次打开的原始文本和元数据，`.logviewer-ai/`保存连接配置、会话/消息快照及隔离工作区；这两个目录不入 Git，备份时一同备份。源码仓库内可选创建的日志和 Agent 文件由使用者管理。现有应用上线之前打开过但未存储的文件无法追溯恢复。

`npm run verify:ai` 验证 v1.2.27 模拟 API 契约，`verify:ai-runtime` 验证受管进程，`verify:history` 验证历史快照。`verify:opencode-live` 需要 `.logviewer-cache/opencode-qa/package/bin/opencode.exe` 的 1.2.27 精确版本测试二进制。测试不使用用户全局 OpenCode 配置，也不调用公网大模型。
